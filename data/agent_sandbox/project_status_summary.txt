Aurora Sync v2.3 successfully migrated from HTTP long-polling to persistent WebSocket channels, resulting in massive performance improvements, notably dropping median sync latency from 4,200 ms to 210 ms. The most critical and urgent issue is #114, a data loss bug that occurs when two devices edit the same file offline and reconnect. This bug must be the top priority for the v2.4 release. Other immediate goals include deploying a jittered backoff fix for reconnect storms (#112). While performance is up, the persistent connection causes a slight, expected increase in mobile battery usage (#121), and the overall timeline remains soft, depending heavily on resolving the data loss bug.
